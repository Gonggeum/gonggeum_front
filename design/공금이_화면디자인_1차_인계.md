# 공금이 화면 디자인 1차 인계

2026-11-10 · 안드로이드 스마트폰 웹앱 검토안 · [클릭 시안](공금이_화면디자인_1차.html)

HTML을 브라우저에서 열고 임의의 아이디와 비밀번호로 로그인한다. 상단 **시안 검토 도구**로 앱 시작 분기, 장부 역할과 잠금, 예산 프리셋, 조회 상태를 바꿀 수 있다. 이 메뉴는 검토 전용이며 앱 화면에는 포함하지 않는다. 거래와 예산은 페이지를 열어 둔 동안 예시 데이터로 동작한다.

## 대상 기기와 검토 기준

안드로이드 스마트폰의 세로 화면을 기본으로 디자인한다. 검토 브라우저는 Android Chrome을 우선 가정한다. 360~430 CSS px에서 세로 흐름을 검토하고, 320 CSS px에서 줄바꿈과 가로 넘침을 확인한다. 넓은 화면 배치는 보조 검토 범위다.

- 주요 메뉴는 하단에 배치하고 44 CSS px 이상의 조작 높이와 시스템 영역 여백을 확보한다. 폭 360 CSS px 이하에서는 거래 폼의 금액·날짜와 필터의 기간 입력을 한 열로 쌓는다.
- 실제 안드로이드 기기에서 키보드를 열고 거래처·금액·메모를 입력한 뒤 저장 버튼과 오류 안내까지 스크롤할 수 있는지 확인한다. 브라우저 뒤로 가기에서 05 호출 화면 복귀와 미저장 입력 처리도 확인한다.
- 09의 카메라·파일 선택, 10의 증빙 첨부, 앱 재진입 시 세션 복원은 실제 기기에서 검증한다. 홈 화면 설치와 오프라인 지원 범위는 별도 제품 결정으로 둔다.

## 검토 순서

1. 기본 진입에서 06 → 00 → 01을 연다. 검토 도구에서 마지막 장부 복원, 팀 없음, 장부 없음, 마지막 장부 접근 불가, 세션 무효, 복원 통신 실패를 골라 **앱 다시 열기**를 누른다.
2. 01 최근 거래 → 05 → 홈으로 돌아간다. 02에서 필터를 조회한 뒤 상세를 열고 돌아와 조건이 복원되는지 확인한다. 01 또는 02에서 10으로 이동해 등록 → 05 상세 → 수정 또는 삭제를 확인한다.
3. 04 → 07에서 미설정, 0원, 양수 예산을 전환한다. 총무·참여자·잠금 상태별로 버튼을 확인한다. 예시의 현재 지출은 470,000원이다. 500,000원 경고·차단 프리셋에서 40,000원 지출을 등록하면 각 초과 결과를 확인할 수 있다.

| 07 | 예산과 이력 로딩 분리 | 미설정, 0원, 양수 및 이력 없음 분리 | 예산 조회 실패는 재시도, 접근 실패는 00. 잠금·일반 참여자는 조회. 설정 저장 실패는 입력 유지 |

## 필드와 저장 확인

- **거래**는 1원~10억 원의 정수 금액과 회계일이 필수다. 지출은 거래처(최대 200자)와 같은 장부의 항목, 수입은 초기 공금·이월·지원금·기부금·기타 중 유형이 필수다. 미래일은 입력 오류, 장부 기간 밖은 서버 확인 흐름이다. 선택 시각을 비워 두면 날짜 단위로 저장한다. 기존 거래의 유형은 수정에서 고정한다. 품목, 거래처 상세 필드, 시각 정밀도는 연결표의 ExpenseInput/Replace 및 IncomeInput/Replace를 따른다.
- **증빙**은 최대 5개, 대표 1개, READY ID만 연결한다. 실패 파일은 등록을 제한한다. 취소 때 새 미연결 파일만 정리하고, 기존 파일은 거래 저장으로 연결을 변경한다. 시안은 파일 이름과 연결 제거를 표현한다. 업로드 처리·대표 선택·마스킹·품목 편집은 개발 규칙으로 인계한다.
- **예산**은 0~10억 원 정수, WARN/BLOCK, 80%/100% 알림, 작업별 변경 사유(최대 500자)로 구성한다. 처음 설정은 기본 사유를 제시하며 해제 후 재설정·금액 변경·해제는 사유를 받는다. 해제는 금액을 NULL로 보내고 정책과 알림 선택을 보존한다. 미설정에서는 게이지·차단·임계 알림이 없고, 0원은 소진율 없이 초과액을 표시할 수 있다. 양수에서 80% 이상 주황, 100% 이상 빨강을 사용하며 초과 비율도 숫자로 표시한다.
- **저장 확인**은 서버의 현재 지출·예상 지출·목표 예산·초과액을 보여 준다. WARN은 취소와 확인 후 저장을 제공한다. BLOCK은 사유와 수정할 수 있는 폼을 표시한다. 현재 지출을 늘리는 요청에서 목표 금액을 초과할 때 적용한다. 설정 자체의 초과 영향 확인은 거래 차단과 별도다.
- **공통 C01~C09**. 제출 중 중복 동작을 제한하고, 같은 의도의 재시도에는 같은 멱등 키를 사용한다. 확인 토큰이 오래됐거나 판정이 바뀌면 최신 금액을 다시 확인한다. 권한 상실 시 보호 데이터와 Blob을 폐기한다. 삭제 대화상자는 취소에 기본 포커스를 둔다. 오류를 필드에 연결하고 상태를 보조기술에 전달한다. 거래·예산 성공 뒤 관련 조회는 C07 기준으로 갱신한다.

### 시안 범위

03·08·09·11과 일부 인증·관리 진입점은 이동 위치를 보여 준다. 실제 API·세션·2FA·초대와 증빙 업로드는 연결표와 백엔드 계약에 따라 구현한다. 시안의 역할 선택기는 장부 권한을 모의하며 팀 OWNER/ADMIN 여부는 개발에서 별도로 판단한다. 거래 행의 페이지네이션과 서버 확인 토큰·버전 충돌도 인계 규칙에 포함한다. BE-03 장기 세션 수명은 회신 대기다.
